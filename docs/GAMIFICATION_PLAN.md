# 어제보다 게임화 시스템 설계

이 문서는 1차 출시 후보에 포함된 게임화 시스템의 설계와 구현 기준이다. 현재 코드에는 기록 조각 적립, 월간 단계 보상, 상점, 인벤토리, 일기·방 꾸미기와 반응형 동물이 구현되어 있다.

## 게임화 시스템 요약

### 기록과 보상의 연결

핵심 순환은 `하루 기록 → 회고 결과 확인 → 보상 확인 → 공간 꾸미기 → 다음 기록`이다. 결과 화면에서는 사용자의 회고 내용을 먼저 보여주고 보상은 두 번째 정보 계층으로 둔다. 기록을 놓쳐도 포인트, 아이템, 공간, 반려동물에 손실이 없다.

- 현실의 성장: 상태와 행동을 돌아보고 내일의 작은 실험을 선택한다.
- 가상의 성장: 기록 조각으로 일기장과 방을 꾸민다.
- 내부 필드명은 `point`, 화면 명칭은 `기록 조각`을 사용한다.
- 기록 한 건의 저장 성공이 보상 판정의 선행 조건이다.
- 동일 날짜의 첫 정상 기록만 일일 기록 횟수와 기본 보상에 반영한다.
- 실제 화폐, 환전, 사용자 간 전송, 확률형 획득과 연결하지 않는다.

### 포인트 획득 방식

| 조건 | 보상 | 지급 방식 |
| --- | ---: | --- |
| 하루 첫 기록 저장 | 10 | 저장 성공 후 한 번만 자동 지급 |
| 공백이 아닌 오늘의 한 줄 | 2 | 일일 기록과 같은 처리 단위에서 한 번만 지급 |
| 월 5회 기록 | 30 | 해당 월 안에 직접 수령 |
| 월 10회 기록 | 70 | 해당 월 안에 직접 수령 |
| 월 15회 기록 | 120 | 해당 월 안에 직접 수령 |
| 월 20회 기록 | 180 | 해당 월 안에 직접 수령 |
| 월 25회 기록 | 250 | 해당 월 안에 직접 수령 |

월간 단계 보상은 누적 지급이다. 예를 들어 15회를 달성하면 5·10·15회 보상을 각각 한 번씩 받을 수 있다. `transaction.type + referenceId`를 멱등 키로 사용하며, 기록 삭제는 이미 생성된 보상 거래를 삭제하지 않는다.

### 월간 목표 구조

- 매일 연속 기록이 아니라 월간 5·10·15·20·25회 구간을 사용한다.
- 진행 화면에서 현재 기록 횟수, 다음 단계까지 남은 횟수, 달성·수령 상태를 표시한다.
- 한 번에 여러 단계를 달성하면 미수령 단계 모두에 수령 버튼을 제공한다.
- MVP의 월간 보상은 해당 달의 로컬 달력 월 안에서만 수령할 수 있다.
- 유예 기간은 향후 `claimExpiresAt` 필드를 추가할 수 있도록 서비스 인터페이스에서 확장한다.
- 연속 출석, 미기록 차감, 소멸 예정 압박 문구는 사용하지 않는다.

### 꾸미기 구조

1차 출시에서는 기록 조각과 일기·방 꾸미기를 하나의 닫힌 로컬 순환으로 제공한다.

- 일기 꾸미기 MVP: 스티커 1개, 마스킹테이프 1개, 일기장 표지 1개 장착
- 방 꾸미기 MVP: 상품별 독립 인스턴스를 허용 구역 안에서 자유 배치
- 장착을 바꿔도 기존 아이템은 인벤토리에 유지
- 자유 드래그와 구매 전 임시 배치를 제공하고 크기 조절·확률형 아이템·거래소는 제외
- 무료 기본 표지·책상·스티커 3개·테이프 1개를 초기 지급

### 장기 성장 구조

| 단계 | 공간 | 권장 조건 초안 |
| --- | --- | --- |
| 1 | 작은 원룸 | 기본 제공 |
| 2 | 넓은 원룸 | 1,000 point + 누적 30회 |
| 3 | 분리형 원룸 | 3,000 point + 누적 90회 |
| 4 | 투룸 | 7,000 point + 누적 180회 |
| 5 | 작은 집 | 15,000 point + 누적 365회 |

방 확장은 포인트와 누적 기록 조건을 모두 충족해야 한다. 반려동물과 가전 상호작용은 기본 기록·경제·구매의 정합성이 검증된 뒤 추가하며, 미접속 불이익이나 실시간 배고픔 감소를 사용하지 않는다.

## 경제 밸런스 초안

### 월간 예상 획득량

계산식은 `기본 10 × 기록일 + 한 줄 2 × 작성일 + 달성한 월간 단계 보상 합계`다.

| 월 기록일 | 한 줄 없음 | 매번 한 줄 작성 | 해석 |
| ---: | ---: | ---: | --- |
| 3 | 30 | 36 | 첫 유료 스티커 진입 |
| 5 | 80 | 90 | 첫 월간 보상, 저가 장식 직전 |
| 10 | 200 | 220 | 저가 장식 또는 입문 가구 |
| 15 | 370 | 400 | 기본 가구 구매권 진입 |
| 20 | 600 | 640 | 중가 가구·표지 선택 가능 |
| 25 | 900 | 950 | 고가 기본 가구 또는 확장 저축 |
| 30 | 950 | 1,010 | 모든 월간 단계 달성 |

예상 핵심 사용자 구간을 월 12~18회로 보면 약 220~436 point다. 15회에서 120 point 보상이 추가되어 획득 속도가 급격히 오르므로 실제 사용 데이터에서 10~15회 구간의 이탈과 구매율을 우선 확인한다.

### 권장 가격

| 종류 | 권장 가격 | 의도 |
| --- | ---: | --- |
| 첫 유료 단품 스티커 | 30 | 2~3회 기록 후 구매 가능 |
| 일반 단품 스티커 | 40~60 | 짧은 목표 |
| 스티커 세트 | 100~180 | 5~10회 기록 목표 |
| 마스킹테이프 | 120~220 | 월 초·중반 목표 |
| 일기장 표지 | 300~600 | 월간 중기 목표 |
| 작은 장식 | 100~250 | 5~10회 기록 목표 |
| 입문 가구 | 220~400 | 10~15회 기록 목표 |
| 일반 가구 | 450~800 | 1~2개월 목표 |
| 고급 가구 | 1,000~2,500 | 장기 선택 목표 |
| 가전제품 | 1,500~4,000 | 3단계 이후 장기 목표 |
| 반려동물 | 2,000~5,000 | 5단계 이후 장기 목표 |

### 첫 구매와 방 확장 예상

- 무료 기본 스티커는 첫 기록 완료 시 지급한다.
- 30 point 스티커는 한 줄 작성 여부에 따라 3회 기록 안에 구매할 수 있다.
- 100 point 장식은 월 5회 보상까지 포함하면 약 6~7회 기록이 필요하다.
- 220 point 입문 가구는 한 줄을 꾸준히 작성하면 10회, 아니면 11~12회 정도가 필요하다.
- 첫 방 확장은 누적 30회와 1,000 point가 필요하다. 월 15회 기록하고 소비하지 않으면 약 3개월, 일부 아이템을 구매하면 약 4~5개월이 예상된다.
- 매일 기록하는 사용자는 한 달에 약 1,000 point를 얻어 30회 조건과 동시에 첫 확장이 가능하다. 속도 차이가 크므로 확장은 최소 30회 조건을 반드시 유지한다.

### 빠르거나 느린 구간

- 5·10·15회 달성 순간 보상이 계단식으로 커진다. 특히 15회 직후 구매력이 크게 증가한다.
- 첫 확장 1,000 point는 월 10회 이하 사용자에게 5개월 이상 걸릴 수 있다. 낮은 비용의 시각적 변화가 충분히 제공되어야 한다.
- 월 25회 사용자는 900 point를 얻어 일반 상품을 빠르게 소진할 수 있다. 고가 상품을 늘리기 전에 계절별 외형 선택과 다양한 저가 조합을 제공한다.
- 한 줄 보너스는 최대 월 60 point로 전체 보상의 작은 비중을 유지해 억지 작성을 유도하지 않는다.
- 월간 보상 합계 650 point가 기본 25일 보상 250 point보다 크다. 초기 운영 데이터에서 인플레이션이 보이면 가격 인상보다 미래 월간 보상표의 완만한 조정을 우선 검토하고, 이미 획득한 자산 가치는 훼손하지 않는다.

## 단계별 구현 계획

### 0단계: 기본 기록 MVP

범위: 6개 선택 단계, 선택적 한 줄, 결과, 로컬 저장, 날짜별 upsert, 초안 복구, 목록·상세·월간 통계.

완료 조건:

- 한 줄 외에는 키보드 없이 전체 기록을 완료한다.
- 앱 재실행 후 기록과 당일 초안이 유지된다.
- 날짜별 기록은 하나이며 목록·상세·통계가 정확하다.
- 날짜 변경, 40자 제한, 최소 선택, 뒤로 이동 시나리오가 통과한다.
- 포인트·상점·방 기능은 노출하거나 실행하지 않는다.

### 1단계: 포인트 기본 구조

범위: 지갑, 거래 원장, 일일·한 줄 보상, 월간 횟수와 직접 수령, 멱등 지급, 잔액 검증.

완료 조건:

- 하루 첫 기록 기본 보상과 한 줄 보상이 한 번만 지급된다.
- 기록 삭제·재작성, 중복 터치, 재실행으로 보상이 복제되지 않는다.
- 월간 횟수와 단계별 수령 상태가 정확하며 여러 단계 동시 달성을 처리한다.
- 지갑 잔액이 거래 합계와 일치하고 손상 시 불일치를 탐지한다.

### 2단계: 일기 꾸미기

범위: 스티커·테이프·표지 카탈로그, 상점, 구매, 인벤토리, 정해진 슬롯 장착과 저장.

완료 조건:

- 부족한 잔액과 영구 아이템 중복 구매를 차단한다.
- 차감과 아이템 지급이 하나의 커밋처럼 처리된다.
- 구매·인벤토리·기록별 장착 상태가 재실행 후 유지된다.

### 3단계: 기본 방

범위: 작은 원룸, 기본 지급 아이템, 고정 슬롯, 가구·장식 구매 및 장착, 방 상태 저장.

완료 조건:

- 보유한 가구만 장착하고 교체한 가구도 인벤토리에 남는다.
- 슬롯별 상태가 저장되고 지원 화면 크기에서 배치가 깨지지 않는다.
- 기록 UX보다 방 진입과 보상 정보가 앞서지 않는다.

### 4단계: 방 확장

범위: 방 레벨, 누적 기록 조건, 포인트 조건, 확장 구매, 슬롯 증가와 외형 변경.

완료 조건:

- 두 조건을 모두 표시하고 미달 시 구매를 차단한다.
- 확장 구매가 한 번만 처리되고 레벨·슬롯·거래가 일치한다.

### 5단계: 반려동물

범위: 조건부 입양, 이름, 대기 반응, 선택적 간식·장난감·액세서리, 친밀도 저장.

완료 조건:

- 미접속이나 미상호작용으로 불이익, 질병, 이탈이 없다.
- 상태와 아이템이 유지되고 확률형 획득을 사용하지 않는다.

### 6단계: 가전과 고급 상호작용

범위: 장식 중심 가전 애니메이션, 계절 테마, 업적, 특별 보상, 이벤트 아이템.

완료 조건:

- 생산 타이머나 필수 반복 행동 없이 선택적 시각 효과로 동작한다.
- 업적 조건과 보상 지급이 멱등하며 기록 강요 문구가 없다.

## 추가 데이터 모델

아래는 구현 전 계약 초안이다. 0단계 저장 데이터와 분리된 버전 키를 사용한다.

```ts
type PointTransactionType =
  | 'DAILY_RECORD_REWARD'
  | 'ONE_LINE_BONUS'
  | 'MONTHLY_MILESTONE_REWARD'
  | 'ITEM_PURCHASE'
  | 'REFUND'
  | 'ADMIN_ADJUSTMENT';

interface PointWallet {
  balance: number;
  totalEarned: number;
  totalSpent: number;
  updatedAt: string;
}

interface PointTransaction {
  id: string;
  type: PointTransactionType;
  amount: number;
  reason: string;
  referenceId: string;
  createdAt: string;
}

interface MonthlyProgress {
  year: number;
  month: number;
  recordCount: number;
  claimedMilestones: Array<5 | 10 | 15 | 20 | 25>;
  updatedAt: string;
  claimExpiresAt?: string;
}

type ShopItemCategory =
  | 'furniture'
  | 'decoration'
  | 'appliance'
  | 'diaryDecoration'
  | 'pet'
  | 'petItem'
  | 'roomExpansion';

interface ShopItem {
  id: string;
  name: string;
  description: string;
  category: ShopItemCategory;
  subcategory: string;
  price: number;
  rarity: 'basic' | 'common' | 'rare' | 'special';
  assetKey: string;
  isConsumable: boolean;
  isAvailable: boolean;
  requiredRecordCount: number;
  requiredRoomLevel: number;
  sortOrder: number;
}

interface InventoryItem {
  id: string;
  itemId: string;
  quantity: number;
  acquiredAt: string;
  acquisitionType: 'PURCHASE' | 'MILESTONE_REWARD' | 'EVENT_REWARD' | 'DEFAULT';
  isNew: boolean;
}

interface EquippedItem {
  slotId: string;
  itemId: string;
  equippedAt: string;
}

interface Purchase {
  id: string;
  itemId: string;
  price: number;
  quantity: number;
  pointTransactionId: string;
  purchasedAt: string;
}

interface RoomState {
  roomLevel: number;
  roomType: string;
  equippedItems: EquippedItem[];
  selectedWallpaper: string;
  selectedFloor: string;
  updatedAt: string;
}

interface PetState {
  petId: string;
  petType: string;
  name: string;
  intimacy: number;
  mood: string;
  equippedAccessories: string[];
  acquiredAt: string;
  updatedAt: string;
}

interface DiaryDecorationState {
  selectedCoverItemId: string;
  defaultTapeItemId: string;
  defaultStickerSetId: string;
  updatedAt: string;
}

interface DailyRecordDecoration {
  dailyRecordId: string;
  tapeItemId?: string;
  stickerItemIds: string[];
  pageBackgroundItemId?: string;
  updatedAt: string;
}
```

핵심 불변식:

- 동일 `type + referenceId` 거래는 하나만 존재한다.
- `wallet.balance = 모든 transaction.amount의 합`이며 사용 거래는 음수다.
- 영구 아이템은 사용자별 `itemId` 하나만 존재한다.
- `Purchase`, 음수 거래, 인벤토리 지급은 하나의 저장 스냅샷에서 함께 커밋한다.
- 장착 아이템은 반드시 현재 인벤토리에 있어야 한다.
- 한 슬롯에는 하나의 아이템만 장착한다.

| 상점 | MVP 3개 카테고리, 가격·보유·적용·미리보기·구매 | 2 |
| 인벤토리 | 보유 아이템, 신규 표시, 필터, 적용·해제 | 2 |
| 방 편집 | 슬롯별 변경, 저장·취소·초기화 | 3 |
| 일기 꾸미기 | 기록 미리보기, 스티커·테이프 고정 슬롯 | 2 |
| 반려동물 | 이름·친밀도·간식·장난감·액세서리 | 5 |

MVP 하단 탭은 `오늘 / 기록 / 내 방`으로 확장한다. 상점은 내 방에서 진입하고 통계는 기록 내부 탭으로 둔다. 0단계에서는 기존 기록 내비게이션만 유지한다.

## 위험 요소와 대응

| 위험 | 대응 원칙 | 필수 검증 |
| --- | --- | --- |
| 포인트 중복 지급 | 거래 멱등 키, 완료 기록 ID 참조, 단일 저장 큐 | 같은 날짜 재저장·삭제 후 재작성·연속 탭 |
| 아이템 중복 구매 | 영구 아이템 보유 검사, 구매 요청 ID | 연속 구매·재실행 후 재구매 |
| 기록·시간 조작 | 보상 원장 보존, 로컬 날짜+마지막 인정 날짜 기록, 역행 탐지 | 월 경계·시간대 변경·시계 역행 |
| 데이터 손실 | 버전 스냅샷, 쓰기 전 검증, 이전 정상본 유지 | 저장 중 종료·부분 JSON 손상 |
| 차감만 되고 미지급 | 거래·구매·인벤토리를 단일 스냅샷으로 커밋 | 각 저장 단계 오류 주입 |
| 잔액 불일치 | 원장 합계 재계산과 지갑 검증, 임의 자동 보정 금지 | 손상된 wallet·transaction 조합 |
| 보상 인플레이션 | 월별 획득·소비·잔액 중앙값 관찰, 가격보다 미래 보상표 조정 우선 | 3·10·15·25·30일 시뮬레이션 |
| 기능 과다 | 단계 게이트, 이전 단계 전체 회귀 테스트 통과 후 다음 단계 시작 | 단계별 기능 플래그·라우트 점검 |
| 게임 우선 UX | 회고 결과를 보상보다 먼저 표시, 홈 1차 행동은 기록 | 사용자 흐름과 정보 위계 리뷰 |
| 죄책감 유도 | 손실·소멸·질병·연속 출석 제거 | 전체 문구 정적 검사와 UX 리뷰 |

로컬 전용 MVP에서는 기기 시간 조작을 완전히 방지할 수 없다. 중복 거래 원장과 날짜 역행 탐지로 반복 획득을 어렵게 만들되, 강한 부정행위 방지는 신뢰 가능한 서버 시간이 있는 후속 아키텍처가 필요하다.

## 이번 단계에서 구현할 기능

- 구현 대상은 기존 기록 MVP인 0단계뿐이다.
- 0단계 모델은 이후 `DailyRecord.id`를 보상 `referenceId`로 안정적으로 사용할 수 있게 불변 ID를 유지한다.
- 포인트, 상점, 인벤토리, 방, 반려동물 코드는 아직 만들지 않는다.
- 1단계 착수 조건은 0단계의 저장·중복 방지·초안 복구·목록·상세·통계와 명시된 회귀 테스트가 모두 통과하는 것이다.
- 1단계 이후는 별도 승인과 별도 작업으로 진행한다.
